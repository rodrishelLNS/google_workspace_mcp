# google_workspace_mcp — full domain

## What it does

Taylor Wilsdon's open-source Google Workspace MCP server, vendored here as the upstream
backend behind `lns-workspace-adapter`. It authenticates against Google and exposes Gmail,
Drive, Calendar, Docs, Sheets, Slides, Forms, Tasks, Chat, Contacts, Search and Apps Script
as MCP tools.

## Architecture

**This repo is not modified here, and that is the point.** HEAD is detached at `d836912`,
`git describe --tags` gives `v1.24.1-1-gd836912`, and `git log upstream/main..HEAD` is
empty — zero local commits on top of upstream. `upstream` is
`taylorwilsdon/google_workspace_mcp`; `origin` is a personal fork with no divergence.
Read it to understand behaviour, never to change it: an edit here is a fork nobody
maintains, and the next pin bump discards it.

Where a change is actually needed, it goes in one of two places. Behaviour that only LNS
cares about — hiding a tool, classifying a write, reshaping a schema, stripping an
argument — belongs in `lns-workspace-adapter`, which was built for exactly that and does
all of it from `lns_workspace_adapter/domain/catalog.yaml` and `domain/domain.py`.
Behaviour that is genuinely a bug in the server goes upstream as a pull request, and the
fix arrives here as a new pin.

Internally it is FastMCP (`core/server.py`), started from `main.py`, which lazily imports
one module per requested service from the map at `main.py:199-210`
(`"gmail": "gmail.gmail_tools"` and eleven siblings). Tools are functions decorated with
`@require_google_service` from `auth/service_decorator.py:714`, which resolves credentials
and injects the authenticated client. `core/tool_tiers.yaml` groups every tool into
`core` / `extended` / `complete` for the `--tool-tier` flag. Auth lives entirely in
`auth/` — OAuth 2.0 and 2.1, service accounts, a credential store, and a callback server.

## Paths that matter

| path | what lives there |
|---|---|
| `main.py` | CLI, flag parsing, service module map, transport selection |
| `core/server.py` | the FastMCP server object and its middleware |
| `core/config.py` | port and identity resolution |
| `core/tool_tiers.yaml` | the `core`/`extended`/`complete` tool groupings |
| `auth/service_decorator.py` | `require_google_service` — how every tool gets a client |
| `g*/` (12 packages) | one `*_tools.py` per Google service, plus helpers |

## Data

No local database. Credentials are the only persisted state, handled by
`auth/credential_store.py`. Identity in single-user mode comes from `USER_GOOGLE_EMAIL`
(`core/config.py:42-45`). The port resolves from `PORT`, then `WORKSPACE_MCP_PORT`,
defaulting to 8000 (`core/config.py:34-38`) — the `:8021` the adapter expects is set by
whoever launches it.

## Conventions

Upstream's, not LNS's. Standards under `platform/standards/` do not apply to this tree,
and neither the naming, the docstring posture, nor the test layout should be read as
guidance for any other repo here.

## Boundary

Consumed by `lns-workspace-adapter` over FastMCP streamable-HTTP; nothing else in the
stack talks to it. It reaches Google directly. Launched as
`uv run python main.py --single-user --transport streamable-http --tools gmail drive
calendar`, which the bifrost-ops harness starts as a sidecar before the adapter.

A pin bump is the one event that matters downstream: it can add, rename or change tools,
and the adapter's `writes` and `gated` lists are keyed on tool names, so re-walking that
inventory belongs to the bump.
